# 项目终端隔离设计

## 目标

每个项目拥有完全独立的交互终端。切换项目时，分别保留各项目的 PTY 会话、屏幕输出、未提交输入和滚动位置；任何项目的输入都只能发送到自己的 PTY。

## 方案比较

1. 切换时销毁并重建终端：改动最小，但无法保留会话和输入，不满足需求。
2. 使用 `KeepAlive` 缓存工作区：可以保留状态，但会连同日志、设置等整个工作区一起缓存，生命周期范围过大。
3. 按项目 ID 常驻终端组件：只缓存需要隔离的终端，边界清晰，采用此方案。

## 组件结构

`App.vue` 根据已访问过交互终端的项目维护终端项目 ID 集合。每个项目渲染一个以项目 ID 为 `key` 的 `Terminal` 组件，只有当前项目且当前标签为“交互终端”的组件可见。

`ProjectWorkspace.vue` 不再持有唯一的终端实例，而是通过事件通知上层激活对应项目终端。终端显示层放在工作区内容区域内，与日志和项目设置面板互斥显示。

## 生命周期与数据流

- 首次打开某项目的交互终端时创建该项目的 `Terminal` 和后端 PTY。
- 切换到其他项目时仅把原终端设为不可见并释放焦点，不调用 `ptyKill`。
- 返回项目时恢复原终端，重新适配尺寸并获得焦点。
- 项目被删除时移除对应终端组件，由卸载流程关闭其 PTY。
- 应用关闭或根组件卸载时，各终端组件分别关闭自己的 PTY。
- 终端内部在初始化时固定本次会话 ID，输入、输出、尺寸调整和销毁都使用该 ID，避免响应式属性切换造成串线或误杀。

## 异常处理

PTY 启动失败仍由现有错误事件显示在对应终端中。隐藏终端不参与尺寸适配；重新显示后执行一次适配。某个项目的终端退出不会影响其他项目。

## 验收标准

- A 中输入但不回车，切到 B 后看不到 A 的输入。
- B 可正常输入和编辑，输入只发送给 B 的 PTY。
- 切回 A 后，A 的未提交输入和已有输出仍保留。
- A、B 的当前目录和 Node.js 环境分别使用各自项目配置。
- 删除项目会结束该项目 PTY，不影响其他项目。
- 连续快速切换项目不会出现终端串线或误杀。

## 验证方式

增加最小组件行为测试覆盖终端 ID 与显示状态的映射，并运行 TypeScript 类型检查和前端构建。Rust 后端数据结构已经按终端 ID 隔离，运行现有 Rust 测试与 Clippy 确认无回归。
