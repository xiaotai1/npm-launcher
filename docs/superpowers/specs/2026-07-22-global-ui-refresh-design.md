# NPM Launcher 全局 UI 统一设计

## 目标

在不改变业务逻辑、IPC 协议和数据结构的前提下，统一 NPM Launcher 的桌面端视觉语言，提升信息层级、长时间使用的舒适度以及浅色/深色主题的一致性。

设计方向采用“专业控制台”：克制、清晰、接近成熟 IDE 和桌面开发工具。界面不追求装饰性视觉效果，状态、操作和日志是视觉重点。

## 范围

本轮覆盖整个渲染进程界面：

- 应用标题栏和 Node 版本选择器
- 项目、文件夹、收藏和批量操作侧栏
- 项目详情、运行状态和项目操作区
- 日志、终端及其工具栏
- 添加/编辑项目表单
- 确认弹窗、错误分析弹窗、Toast 和右键菜单
- 空状态、加载状态、悬停状态、选中状态和键盘焦点
- 浅色、深色及跟随系统主题

本轮不新增功能，不修改 Electron 主进程、preload API、配置格式或进程管理行为。

## 视觉系统

### 色彩

以冷静的蓝灰中性色为基础，蓝色仅用于主操作和选中状态。绿色、黄色、红色分别表示成功、警告和错误，不能只依赖颜色传递状态，需同时保留文字或图标提示。

全局颜色通过语义化 CSS 变量提供，组件不直接散落新的十六进制颜色。浅色主题采用浅灰底和白色工作区；深色主题采用深蓝灰导航与近黑控制台，避免纯黑和高强度发光效果。

### 字体

- 界面字体继续使用系统无衬线字体栈，正文基准为 14px。
- 应用标题使用 13px、约 650 字重，不与内容标题竞争。
- 项目名称和区域标题采用 14–18px 的清晰层级。
- 路径、端口、Node 版本、PID 和日志使用系统等宽字体栈。
- 辅助文字不得小于 11px；长文本保持至少 1.5 的行高。

### 间距、圆角与阴影

- 采用 4px 基础间距，常用间距为 8、12、16、20、24px。
- 控件圆角以 6–8px 为主，弹窗和大型容器使用 12–14px。
- 普通组件依赖边框区分层级；阴影只用于下拉菜单、弹窗和 Toast。
- 删除无意义的渐变、发光和装饰性阴影，避免多个组件同时争夺注意力。

## 布局与组件

### 标题栏

标题栏保持 48px 高。应用内部只显示 `NPM Launcher` 文字，不展示品牌图标。现有 `build/icon.svg`、PNG 和 ICO 继续用于安装包、Dock、任务栏和系统级入口。

macOS 标题从系统红绿灯按钮之后约 12px 开始；Windows 使用约 20px 左边距，并保留自定义最小化、最大化和关闭按钮。右侧保留 Node 版本选择器和主题切换，使用紧凑、无发光的工具栏样式。

### 项目侧栏

侧栏使用稳定的深色导航面，即使主内容处于浅色主题也保持清晰分区；深色主题下通过边框和层次差区分。

- 顶部显示“项目”和新增按钮。
- 搜索、收藏、文件夹、未分组项目具有明确层级。
- 项目行同时显示名称、运行状态和必要的辅助信息。
- 选中项使用低饱和背景和窄蓝色指示条，不使用大面积渐变。
- 收藏、拖拽目标、右键操作和折叠状态继续沿用现有行为。
- 批量启动/停止位于侧栏底部，与单项目操作分离。

侧栏宽度继续支持拖拽调整和折叠，现有本地持久化逻辑保持不变。

### 项目详情

项目详情顶部形成单一工作流：

1. 项目名称、路径和启动命令。
2. 运行状态、Node 版本和进程信息。
3. 启动/停止作为唯一主操作，编辑、打开目录等作为次级操作。

运行状态使用圆点、文字和语义色组合。没有选中项目时显示有明确下一步的空状态，不展示无意义占位卡片。

### 日志与终端

日志/终端占据主要工作区，成为界面的视觉中心。

- 标签切换放在控制台上方，当前标签使用细底边强调。
- 自动滚动、清空、导出和错误分析放入同一工具栏。
- 控制台使用高对比等宽字体，时间戳、信息、警告、错误和成功具有稳定色彩映射。
- 控制台容器避免额外卡片嵌套和强阴影。
- xterm 主题颜色与全局控制台变量保持一致。

### 表单、菜单与反馈

- 表单采用始终可见的字段标签，错误信息显示在对应字段附近。
- 主按钮、次按钮和危险按钮形成统一层级；按钮高度和内边距保持一致。
- 确认弹窗、错误分析弹窗、Toast、下拉菜单和右键菜单共用边框、圆角、阴影和动效规范。
- 空状态说明发生了什么，并提供用户可以立即执行的动作。
- 删除等危险行为继续经过确认，不改变当前业务流程。

## 交互与动效

- 常规悬停和焦点反馈持续 150–200ms；弹窗和下拉菜单持续 200–250ms。
- 动效用于解释状态变化，不对静态装饰进行循环动画。
- 禁用状态需要同时改变透明度和鼠标/键盘行为。
- 所有图标按钮提供 `title` 或 `aria-label`。
- 可交互控件提供清晰的 `:focus-visible` 样式，不能移除键盘焦点提示。
- 在 `prefers-reduced-motion: reduce` 下关闭非必要位移和缩放动画。

## 响应式与平台差异

应用仍以桌面窗口为主要场景。较窄窗口下优先保证控制台可用：侧栏可折叠，项目操作允许换行，状态信息减少为关键字段，不产生水平页面滚动。

macOS 使用系统红绿灯和隐藏式标题栏；Windows 使用现有自定义窗口按钮。两端共享同一视觉变量和组件层级，但保留平台必要差异。

## 实现边界

优先重构现有 `main.css` 语义变量和组件样式，不引入新的 UI 框架或远程字体。现有 Vue 组件边界、事件、属性和 Electron API 保持稳定；仅在样式复用确有收益时添加轻量展示组件。

## 验证

实施完成后需要：

- 运行 TypeScript 类型检查。
- 运行生产构建。
- 检查浅色、深色和跟随系统主题。
- 检查 macOS 与 Windows 标题栏布局逻辑。
- 检查侧栏折叠、拖拽调整、项目选择、项目表单、弹窗、Toast、日志/终端标签和 Node 版本下拉菜单。
- 使用实际应用截图复查布局、对比度、焦点样式和窄窗口表现。
- 确认现有业务交互和 IPC 调用未发生变化。

## 验收标准

- 所有主要区域使用同一套颜色、间距、字体、圆角和交互状态。
- 标题栏不显示应用图标，系统级图标资产保持不变。
- 主要操作和运行状态可在一次扫视中识别。
- 浅色与深色主题均无低对比文本、突兀发光或不一致组件。
- 日志和终端在常用窗口尺寸下保持最大的有效阅读区域。
- 类型检查与生产构建通过，现有功能没有回归。
